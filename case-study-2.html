1 · The task

What was asked

An aluminium support bracket (E = 70 GPa, Poisson ratio 0.33), 189 mm tall, standing on two feet with a seat on top. It is one design from the AgentFEM bracket family.

The undersides of the feet (every face at z = 0) are fixed. The top seat face (z = 189 mm) is pushed straight down with 10 kN in total, about the weight of one tonne.

How far does the seat sink on average, and what is the biggest movement anywhere in the bracket?

Input

geometry.stepthe bracket as a 3D CAD file (mm), one solid

Output

{
  "outputs": {

    "max_displacement_mm": <number>         // mm, biggest movement anywhere
  }
}

plus 7 more files (mesh, result fields, solver log, refinement record, …). Pass if each value is within ±10 % of the reference and expert human annotators sign off the workflow.

Exact prompt Astra received
Support bracket (one member of a parametric double-arm bracket family). geometry.step holds one solid in millimetres (height 189 mm).

Material: linear isotropic elastic, E = 70 GPa, Poisson ratio 0.33 (density 2700 kg/m^3, gravity not applied).
Supports: the foot undersides, i.e. every face lying in the plane z = 0, are fully fixed (all displacement components zero).

Analysis: 3-D linear elasticity, small displacements. The publisher used quadratic tetrahedra with a nominal 9 mm mesh.

Outputs:

- max_displacement_mm [mm]: maximum displacement magnitude anywhere in the bracket

2 · What Astra did

Its program, step by step

One call to GPT-6 Astra (medium reasoning, no tools, no feedback) returned one Python program of about 450 lines. The generation cost $0.17. We ran it once, offline. It stopped after 0.45 seconds.

  1. Loaded geometry.step with Gmsh and checked it holds one solid. Correct.
  2. Checked the part's size with Gmsh's quick bounding box and demanded that it start at z = 0 and end at z = 189 mm to within 0.0001 mm. That box is loose around curved surfaces: for this bracket it reaches z = −1.39 mm. The check failed and the program raised an error: Unexpected CAD height or position.
  3. Planned next, never reached: find the foot and seat faces, mesh with quadratic tetrahedra at 9, 6.75 and 5.4 mm, solve with CalculiX for each mesh, check force balance, and write the two values.

The CAD was right. Measured exactly, the bracket runs from z = 0 to z = 189 mm, just as the prompt says. Only the quick box is loose, because it is built around the control points of the curved arms, not the surface itself.

3 · The input file and Gmsh

What geometry.step is, and how Gmsh reads it

The bracket reaches the model as one file, geometry.step. Astra's program opened it with Gmsh, the open-source mesher in the sandbox. Here is what is inside the file and what Gmsh does with it.

Inside geometry.step

A 230 KB text file in the STEP format (ISO 10303-21), written by Open CASCADE. It does not store triangles or pixels: it describes the exact surfaces of the part, a boundary representation.

What Gmsh does with it

  1. Import. Gmsh hands the file to its OpenCASCADE kernel, which rebuilds the exact shape. Gmsh then sees numbered entities by dimension: 40 points, 64 curves, 24 surfaces, 1 volume.
  2. Quick size. getBoundingBox(3, tag) asks OpenCASCADE for a fast box around the volume. For a B-spline surface it boxes the control points, not the surface. This is the call Astra's check used.
  3. Mesh, in order of dimension. First the curves are cut into segments (1D), then the surfaces into triangles (2D), then the volume into tetrahedra (3D).
  4. Curved elements. setOrder(2) adds a node in the middle of every edge and moves it onto the exact CAD surface, so elements follow the curved arms. If an element is large compared with the curvature, this move can fold it inside out.
  5. Exact size, if asked. With the option Geometry.OCCBoundsUseStl = 1, Gmsh measures the box from the surface itself and returns exactly z = 0 to 189 mm.

4 · The math, without any tolerance

Why the check had to fail

This failure is not about a band being too strict. Both of Astra's bugs follow from the math of the geometry, and each gives a yes-or-no answer.

The control-point hull

A B-spline surface is S(u, v) = Σ Ni(u)·Nj(v)·Pij, where the Pij are control points and the weights N are never negative and always add up to 1. So every point of the surface is a weighted average of the control points, and lies inside their convex hull. A box around the control points therefore always contains the surface, but is usually bigger.

The numbers in this file

The arms' control points reach z = −1.392 mm and y = −64.833 mm: exactly the numbers in Astra's error message. The arm surfaces themselves start at z = 18.0 mm and y = −23.6 mm, and the whole part at z = 0 and y = −40 mm. Comparing an outer box with exact numbers to 0.0001 mm was bound to fail for this file. Any tolerance under 1.39 mm fails the same way.

The inside-out element

Each element maps a perfect reference tetrahedron onto the part: x(ξ) = Σ Na(ξ)·xa. The stiffness is an integral weighted by det J, the determinant of ∂x/∂ξ, which is the local volume ratio. It must be positive everywhere. When moving mid-edge nodes onto the curved arm folds an element, det J ≤ 0: negative volume, and CalculiX stops with "nonpositive jacobian".

So: logic errors, not accuracy

Neither bug is a number slightly off. The first compares a guaranteed over-estimate with exact values; the second builds an element with negative volume. Each is a yes-or-no fact about the program, true for any tolerance on the answer.

5 · What if the check had not been there?

One line changed, and the numbers pass

We reran Astra's own program in the same sandbox with the same limits, changing only the line that raises the error (to pass). Nothing else was touched.

Its setup was right: 63 146 nodes, 36 544 quadratic tetrahedra, the full 10 kN applied, and the supports pushing back with the same 10 kN (force balance to 3 parts in a billion). The run took 14 seconds.

A second, hidden problem. Even with the check removed, its second, finer mesh (6.75 mm) failed: CalculiX stopped with nonpositive jacobian, meaning one curved element was turned inside out. So the program could show only one mesh level, and the required convergence record would be incomplete. The numbers would pass, but the expert human annotators would not be able to sign off convergence.

What would have avoided it

  • Use an exact size measurement (Open CASCADE's optimal bounding box) instead of the quick one, or allow a sensible tolerance such as 0.5 mm.
  • Warn instead of stopping: a size check that disagrees with the prompt is worth logging, not worth giving up the whole task over.
  • Straight-sided (not curved) quadratic elements, or a mesh-quality check before solving, would have avoided the inside-out element on the finer mesh.

7 · Possible limitations

What this one case does not prove

One try, no feedback

Astra wrote its program blind. Seeing the error message once might well have been enough to fix it: our one-line change shows how small the fix is.

One sample

We ran this task once. Another sample could skip the size check or use a looser tolerance and pass.

A strict rule, fairly applied

Failing on a 1.4 mm box error looks harsh, but the benchmark only reads what the program writes. A program that stops gives no answer, whatever it would have found.

Our "what if" is our edit

The passing numbers come from our one-line change to Astra's code. They show how close it was; they are not Astra's result and do not count.

Software detail, not physics

The failure comes from how Gmsh measures curved shapes. It tests careful use of tools more than engineering knowledge.

Reference from the source

The reference values come from the AgentFEM publisher's own simulation (quadratic tetrahedra, 9 mm mesh). We did not reproduce this task independently; Astra's program, check removed, agrees with it to 2 %.

Our sandbox, our limits

Astra's run had 10 minutes and 6 GB of memory. It stopped in half a second, so the limits played no part.
